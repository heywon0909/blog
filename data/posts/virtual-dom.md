## 가상 DOM

React에서는 가상 DOM을 활용하여 업데이트를 진행한다. 가상DOM이란 DOM 과 비슷하게 HTML 문서를 자바스크립트 객체로 변환한 것이다.
실제 DOM은 노드 객체로 구성되고, 가상 DOM은 JS 객체로 구성된다는 점에서 큰 차이가 있다.

## 가상DOM을 왜 쓸까

React에서 가상 DOM을 쓰는 이유는 실제 DOM의 문제점을 완하하기 위해서 이다.

1. 잦은 reflow는 CPU 효율성을 떨어뜨린다.
   실제 DOM에서 레이아웃의 변화가 일어나면 다시 브라우저가 문서의 전체나 일부 레이아웃을 다시 계산하는 reflow가 일어나는데 잦은 reflow는 CPU 효율성을 떨어뜨릴 수 있다.

2. 브라우저 호환성
   브라우저간 이벤트 속성에 접근하는 방식이 달랐다. 예를 들면 event.target을 사용하는 경우가 있고, event.srcElement를 사용하는 경우가 있다.

## React에서의 가상 DOM을 Smart하게 활용한다.

리액트는 이전 가상 DOM 과 새로운 가상 DOM 을 비교하여 실제 DOM 업데이트에 필요한 최소한의 변경사항을 결정한다.
이때 Diffing 알고리즘을 사용하여 둘의 차이점을 식별한다.
리액트의 Diffing 알고리즘은 고도로 최적화되어있으며 실제 DOM에 적용해야하는 변경 횟수 최소화를 목표로 한다.

두 트리의 루트에 있는 노드가 다른 경우, 리액트는 기존 트리 전체를 새 트리로 대체한다.

루트 노드가 동일하다면 리액트는 노드의 속성이 변경된 경우에만 업데이트한다.

자식 노드가 다른 경우 리액트는 변경된 자식 노드만 업데이트한. 리액트는 하위 트리 전체를 다시 생성하지 않고 변경된 노드만 업데이트 한다.

노드의 자식들이 동일하지만 순서가 변경된 경우, 리액트는 노드를 다시 생성하지 않고 실제 DOM에 노드의 순서를 다시 설정한다.

트리에 새 노드가 추가되면 리액트는 해당 노드를 실제 DOM에 추가한다.

트리에서 노드가 제거되면 리액트는 실제 DOM에서 노드를 제거한다.

노드의 종류가 변경된 경우(예: div에서 span으로 변경), 리액트는 이전 노드를 제거하고 변경된 종류의 새 노드를 생성하나.

노드에 key 프롭이 있다면, 리액트는 이럴 사용해 노드의 교체가 필요한지 파악한다. 컴포넌트 상태를 재설정할 때 유용하다.
