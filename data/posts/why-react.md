## React 를 왜 쓸까? 아니 왜 필요해졌을까?

이유를 정리해보면 총 2가지이다.

첫번쨰, 즉각적인 업데이트에 대한 needs 다.
업데이트를 위해 새로운 페이지를 렌더링하고 로딩될때까지 기다려야했던 기존의 웹과 달리 새로운 페이지를 렌더링하지 않고, 업데이트되어 내용을 확인하고 싶어하는 needs 가 증가했다.

두번쨰, 대규모 애플리케이션을 쉽고, 효율적으로 만들고 싶어서이다.
웹페이지를 업데이트하면 브라우저가 html을 파싱하여 DOM 트리를 구축하고, css 를 파싱하고 css 트리를 구축하고 둘을 결합하여 렌더트리를 구축하고, 뷰포트 기반으로 렌더트리의 각 노드가 가지는 정확한 위치와 크기를 계산하여 화면에 그리는 과정 reflow 거쳐야한다..
만약 업데이트가 여러번 발생할 경우, reflow 작업으로 인한 성능 병목현상이 발생한다.
또한 여러 사람이 작업하는 코드베이스에서 상태관리 방식이 통일되지 않으면 코드의 일관성을 유지하는데 어려움이 따릅니다.
XSS,CSRF와 같은 악용을 방지하기 위해 페이지에 삽입되는 HTML과 자바스크립트를 확인해 문제가 될만 한 부분을 제거해야했다.

## React 는 무엇일까

이러한 이유로 React 가 등장하게 되었다.
리액트는

1. 컴포넌트 기반 모델
2. flux 의 단방향 흐름을 원칙
3. 불변 상태
4. 가상 DOM
   이렇게 정리할 수 있다.

### 리액트는 컴포넌트 기반 모델이다.

리액트는 컴포넌트 기반으로, 이들을 조합하여 애플리케이션을 구성할 수 있게 한다.

### Flux 의 단방향 흐름

리액트는 MVVM과 달리 Flux의 단방향 흐름을 원칙으로 하여 데이터 흐름을 예측 가능하게 한다.
Flux의 개념을 살펴보면 액션(사용자인터렉션) 발생 시, 디스패쳐에서 해당 액션을 스토어로 전송하고 스토어에서 액션관련 상태를 업데이트하고 사용자 화면인 뷰에 반영한다.
React는 이 Flux의 단방향 흐름을 원칙으로 데이터가 상위 컴포넌트에서 하위 컴포넌트로 단방향으로 흐르게 한다.

### 불변 상태

리액트는 애플리케이션의 상태를 변하지 않는 값으로 기술한다. 상태가 변경되면 원래 상태를 직접 변경하는 대신 새로운 상태를 표현하는 새 객체를 반환한다. 이를 통해 변경 사항을 추적하고, 디버깅하기 쉬워진다.

### 가상 DOM

리액트는 업데이트가 발생하면 직접 DOM에 업데이트하여 reflow가 발생하는 기존의 방식과 다르게 가상 DOM을 활용하여 업데이트 내용을 가상 DOM에 반영 후, 반영된 내용을 한꺼번에 DOM에 업데이트한다.

## 리액트의 선언형 프로그래밍

리액트를 쓰면, 개발자가 화면에 어떻게 나타낼지만 리액트 방식대로 선언적으로 작성하면, 리액트가 내부적으로 가상 DOM을 활용해 실제 DOM을 효율적으로 업데이트 할 수 있게 해준다.
